## 三、遇到的问题

1. **飞鸟过管循环每帧抛错（最严重）**：`flappy.js` 里 `prev` 只声明未初始化，`prev[k] = env.pad[k]` 抛 `TypeError`，被 `engine` 的 `try/catch` 吞掉后只写 `console.error`，表现为「能点、HUD 变、但鸟不动也不结算」。修复：`var prev = {}` 并在 `reset()` 中重置。教训：`engine` 会吞掉循环内异常，自测时不能只看「页面没崩」。
2. **弹珠台 3 秒丢 3 球**：`loseBall()` 只 `balls--`，没有立刻停机，球停在界外导致 `state` 仍为 `play`，物理继续跑 → 每帧判丢一次。修复：进入 `state='lost'` 暂停物理，600ms 后再回到 `ready`，渲染时 `state==='lost'` 不画球。
3. **弹珠台发射后从不进入主战场**：发射道顶部导流线段方向写反（`{524,64}→{450,108}` 的下侧法线指向右下），球被弹回通道直落，Bumper 撞击恒为 0。改为左上→右下 `{455,64}→{524,118}`（下侧法线指向左下），顶棚右端同步对齐 455，球现在稳定折入主战场。
4. **快速按键在帧间被漏掉**：`playwright`/自动化按下抬起过快时，`pad` 边沿检测（每帧比对 `prev`）会整帧错过输入。三款统一改为「`onKey` 直触发 + 冷却去重（flappy 80ms / pinball 120ms）」，`pad` 边沿仅作兜底，键盘与触屏两条通道不会重复触发。
5. **五子棋点击必须精确命中交叉点**：原判定要求点击落在交叉点 `STEP*0.55` 半径内，触屏手指粗容易点空。放宽为 `STEP*0.85`（整格吸附到最近交叉点）。
6. **开局 HUD 被覆盖**：`play.html` 在 `GameKit.run` 后会 `renderHud({score:0})`，覆盖 `reset()` 里设置的生命/状态，玩家开局看不到球数等信息。三款在 `start()` 中补一次 `env.hud(...)` 同步。
7. **测试工具与手法**：`agent-browser` 守护进程在读取大量 console 后易卡死（连不上旧端口），改用 `playwright-cli`（`run-code --filename` 可加载脚本文件，用 `keyboard.down/up` 精确控制按键时长）。另外合成 `KeyboardEvent` 只发 `keydown` 不发 `keyup` 会让 `pad` 永久卡在 true、后续边沿全部失效，自动化必须成对发送或直接用真实按键。
